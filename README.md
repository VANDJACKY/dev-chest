# dev-chest · 开发零碎资料库

> 定位：**开发过程随手存放的杂项文件库** —— 零碎但有用的资料、AI 生成的小脚本、临时文档、小需求 / 小问题笔记、代码片段备忘。
> 这里不是正式项目，不追求工程完整性，只追求「需要时找得到、拿来就能用」。

## 目录结构

```
dev-chest/
├── README.md          # 本说明
├── docs/              # 笔记 / 指南类文档（环境搭建、踩坑记录、方案备忘）
├── scripts/           # 小脚本（shell / python 等，可独立运行的工具）
├── snippets/          # 代码片段（不独立成文件运行的参考代码）
├── notes/             # 小需求 / 小问题 / 临时想法的记录
└── .qoder/rules/      # Qoder IDE 上下文规则（新窗口对话时自动了解本仓库定位）
```

## 命名约定

- **目录内文件**：全小写 `kebab-case`，英文为主，避免空格和中文文件名（终端处理麻烦）
- **有时效性的笔记 / 文档**：日期前缀 `YYYY-MM-DD-主题.md`，如 `2026-10-20-macos-jdk8-maven-switch.md`
- **长期参考型文档**：不带日期，如 `macos-jdk-switch-guide.md` 这种主题明确的可持续更新
- **脚本**：动词或功能名，如 `usejdk.zsh`、`cleanup-dsstore.sh`
- 脚本首部尽量写一行注释说明用途，方便 grep

## 使用习惯

- 新增分类直接在根目录建文件夹即可，同时在上方「目录结构」补一行
- **隐私红线**：任何文件内容中不得出现账户密码、token、IP、邮箱、手机号等个人或敏感信息，写入前先检查脱敏；含秘密的本地副本用 `*.local` 命名（已被 git 忽略）
- 大文件（>10MB）不要入库；`.gitignore` 已屏蔽常见压缩包 / jar / 日志
- macOS 垃圾文件（`.DS_Store` 等）已全局忽略
- 本仓库配合 Qoder 使用时，`.qoder/rules/repo-context.md` 会让 AI 窗口自动了解仓库定位
