# dev-chest 仓库上下文

本仓库是个人**开发杂项资料库**，不是正式项目。定位：零碎但有用的资料、AI 生成的小脚本、临时文档、小需求/小问题笔记、代码片段的随手存放。

## 行为约定

- 不追求工程完整性（无需构建脚本、测试、CI 等），不要主动补建
- 新增内容按现有目录归类：`docs/`（文档笔记）、`scripts/`（可运行小脚本）、`snippets/`（代码片段）、`notes/`（需求/问题记录）；分类不够用时可直接新建目录，并同步更新 README 的目录结构一节
- 文件命名：小写 kebab-case 英文；有时效性的笔记用 `YYYY-MM-DD-主题.md` 前缀
- 脚本要可独立运行，首部注释说明用途
- **隐私与敏感信息红线（最高优先级）**：所有内容中不得出现个人隐私与敏感信息——账户密码、token、私钥、IP 地址、邮箱、手机号、姓名/住址等任何与个人相关的信息；敏感信息不入库，含秘密的本地副本用 `*.local` 命名（已被 .gitignore 忽略）；写入前必须扫描检查，发现即提醒并脱敏
- 大二进制不入 git（.gitignore 已屏蔽 zip/jar/dmg 等）

## 粘贴文件（无附加说明）的默认处理

当用户只粘贴/丢进一个文件、不附带任何说明时，默认按「**判断类型 → 归类存放 → 改名/加注 → 汇报**」流程处理，不反问：

1. **读内容、判类型**：脚本 / 文档笔记 / 代码片段 / 需求或问题记录
2. **归类存放**：脚本进 `scripts/`（首部补一行用途注释），文档进 `docs/`（有时效的加 `YYYY-MM-DD-` 前缀），片段进 `snippets/`，需求/问题进 `notes/`
3. **合规检查**：文件名转小写 kebab-case 英文；按上方隐私红线扫描敏感信息（密码/token/IP/邮箱等，有则提醒并脱敏或改存 `*.local`）；大二进制不入库
4. **新建目录时**同步更新 README 的目录结构一节
5. **完成后简短汇报**：存放位置、归类理由、所做调整（如改名）

若用户只想「看内容/分析/改写」而不存档，说一句「只看不存」即可跳过入库。

详细命名与使用习惯见根目录 `README.md`。
